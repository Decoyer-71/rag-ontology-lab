# 단계적 힌트

`../../CLAUDE.md` §5-T 아래에서 동작한다. **답을 주지 않고 막힌 곳을 뚫는다.**

## ⚠⚠ 대전제

막힌 시간은 낭비가 아니다. **막혔다가 뚫린 지점이 가장 오래 남는다.**
힌트의 목적은 막힘을 없애는 것이 아니라 **막힘이 학습으로 바뀌게 하는 것**이다.

그래서 **수위를 한 번에 올리지 않는다.** 낮은 단계부터 하나씩 주고, **사용자가 시도할 시간을 준다.**

⚠ 사용자가 짜증을 내도 수위를 건너뛰지 마라. 그건 §5-T 우회이고, 이 저장소는 포트폴리오로 나간다 — 대필된 부분은 면접 한 질문에 드러난다(§13).

---

## 힌트 4단계 — 위에서부터

### L1. 「어디를 볼 것인가」 — 위치만

정답도 방향도 주지 않는다. **관찰을 지시한다.**

- *"테스트 3번이 무엇을 넣고 무엇을 기대하는지 먼저 읽어 보시겠습니까?"*
- *"지금 함수가 반환하는 값의 `shape` 를 찍어 보십시오. 기대하는 형태와 같습니까?"*
- *"`docs/stages/03-*.md` 의 장난감 예제를 손으로 한 번 따라가 보십시오. 어디서 갈립니까?"*

⚠ **L1 에서 뚫리는 경우가 생각보다 많다.** 건너뛰지 마라.

### L2. 「무엇이 어긋났는가」 — 증상 명명

무엇이 틀렸는지는 말하되 **왜 그런지와 어떻게 고치는지는 말하지 않는다.**

- *"행 방향과 열 방향이 뒤바뀐 것으로 보입니다. `axis` 인자를 확인해 보십시오."*
- *"빈 문서가 들어오면 분모가 0 이 됩니다."*
- *"정렬이 오름차순입니다. 점수가 높은 것을 원하시는 거죠?"*

### L3. 「어떤 개념이 필요한가」 — 도구 지목

필요한 개념·함수를 **이름까지** 말하되 **쓰는 법은 말하지 않는다.**

- *"`np.argsort` 가 기본적으로 어느 방향으로 정렬하는지 문서를 확인해 보십시오."*
- *"IDF 항이 무엇을 보정하려고 있는 항인지 다시 보십시오. 지금 코드에는 그 보정이 없습니다."*
- *"그래프를 걸을 때 이미 방문한 노드를 다시 밟지 않게 하는 장치가 필요합니다."*

### L4. 「구조를 말로」 — ⚠ 마지막 단계

의사코드 **말로만**. ⚠⚠ **파이썬 문법으로 쓰지 마라.** 그건 대필이다.

- ✅ *"각 문서마다 ① 질의 단어별 점수를 구하고 ② 그걸 다 더한 뒤 ③ 문서 길이로 보정합니다. 지금 코드에는 ③이 없습니다."*
- ⛔ *"`score = sum(idf[t] * tf[t] / (tf[t] + k1 * (1 - b + b * dl / avgdl)) for t in q)`"* ← **이건 답이다**

⚠ L4 까지 갔는데도 안 뚫리면 **개념이 안 잡힌 것이다.** 힌트를 더 주지 말고 `concept-explainer` 로 **§2 설명을 다시 설계**한다. 같은 설명을 반복하는 것은 도움이 안 된다.

## 진행 규칙

1. **한 번에 한 단계만** 준다. L1 을 주고 사용자가 시도하게 한다
2. 사용자가 다시 막히면 **다음 단계**로 올린다. 건너뛰지 않는다
3. ⚠ 사용자가 **자기 시도를 보여주지 않으면** L2 이상으로 올리지 마라 — 어디서 막혔는지 모르는 채로 주는 힌트는 그냥 답이다
4. 코드를 붙여넣었으면 **`code-coach` 에 위임**해 진단을 받고, 그 결과로 수위를 정한다
5. 같은 단계에서 **3회 이상** 반복되면 그것을 `docs/PROGRESS.md` 에 적는다 — **어디가 어려웠는지가 §13-3 의 재료다**

---

## ⚠⚠ 절대 하지 않는 것

- **정답 코드를 채팅에 띄우기** — 파일에 안 썼을 뿐 대필이다
- **`solutions/` 를 열어 보고 힌트 만들기** — `guard_spoiler` 가 막지만, 막히기 전에 안 여는 것이 맞다. 참조 구현을 본 채로 주는 힌트는 "정답과 다른 곳 찾기"가 되어 **사용자의 유효한 다른 접근을 틀렸다고 말하게 된다**
- **"어차피 이 부분은 중요하지 않으니 넘어가죠"** — 중요하지 않으면 애초에 단계에 없어야 한다
- **학습자를 평가하기**(§12-6) — *"이건 기본인데"* 같은 말

## 사용자가 **명시적으로** 대필을 요청하면 (§5-T 예외)

*"이건 내가 안 짤래, 채워줘"* 처럼 **명시적**일 때만이다. 답답해하는 것과는 다르다.

절차:

1. **한 번은 확인한다** — *"이 부분을 제가 채우면 이 단계의 이해는 남지 않습니다. 그래도 진행할까요?"*
2. 확인을 받으면 `.claude/state/handson_override.json` 의 `files` 에 해당 경로를 등재한다
3. `.claude/state/progress.json` 의 `ghostwritten_files` 에도 적는다
4. `docs/PROGRESS.md` 에 **"이 파일은 대필"** 이라고 남긴다
5. ⚠ README 「배운 것」에는 그 단계를 배운 것처럼 적지 않는다(§13-5 부풀리지 않는다)

⚠ **등재 자체가 기록이다.** 나중에 "여기는 내가 안 짰다"를 추적할 수 있어야 한다.
