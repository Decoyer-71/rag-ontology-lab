# 다음 학습 단계 수행 절차

`../../CLAUDE.md` §7 의 실행 절차다. **단계를 받자마자 개념 설명부터 쏟아내지 않는다.**

이 저장소의 산출물은 *돌아가는 RAG* 가 아니라 **「사용자의 이해」** 다. 절차 전체가 그것을 만들기 위한 것이다.

## 언제 쓰는가

**쓴다** — 새 단계를 시작할 때, 새 세션에서 학습을 재개할 때.

**안 쓴다** — 진행 중인 단계의 다음 대화(그냥 이어서 한다), 단순 질문("Recall 이 뭐예요"), 환경 문제 해결.

## 0. ⚠⚠ 진도부터 읽는다

```bash
.venv/Scripts/python.exe -c "import json;print(json.load(open('.claude/state/progress.json',encoding='utf-8')))"
```

⚠ 인라인 `-c` 는 따옴표가 깨질 수 있다(§6 지뢰 3). 그냥 `Read` 로 열어도 된다.

**이걸 안 하면** 이미 끝난 단계를 다시 설명하거나 아직 안 배운 개념을 전제로 말하게 된다. 컨텍스트는 요약되면 사라지지만 이 파일은 남는다.

### 0-1. ⚠⚠ 미확정 가정이 남아 있으면 **먼저 확인한다**

`progress.json` 의 `assumptions_unconfirmed` 가 `true` 면 `CLAUDE.md` §0-2 의 세 가지(코퍼스 도메인 / 실습 강도 / Stage 9 조달 시점)를 **한 번에 모아** 묻는다(§12-3 — 확인이 여럿이면 모아서).

확인을 받으면 §0-2 표를 **결정으로 교체**하고(§5-K'), `assumptions_unconfirmed` 를 `false` 로 바꾼다.

## 1. 능력 목표를 한 문장으로 먼저 말한다

기능이 아니라 **능력**으로 적는다.

| 나쁜 예 | 좋은 예 |
|---|---|
| "BM25 를 구현합니다" | "왜 벡터 검색만으로는 요금제 코드 `LTE-S-33` 을 못 찾는지 설명하고, 그 구멍을 메우는 검색기를 짤 수 있게 됩니다" |
| "청킹을 배웁니다" | "글자수로 자르면 요금표가 어떻게 깨지는지 **측정으로 보이고**, 구조 단위로 자르는 코드를 짤 수 있게 됩니다" |

⚠ 사용자가 이 문장을 읽고 *"그게 왜 필요한데?"* 라고 물으면 아직 §2 가 안 된 것이다.

## 2. 직관 → 원리 → 그림 (`concept-explainer` 위임)

`concept-explainer` 에 위임해 골자를 받고, **`verify` 를 통과시킨 뒤** 사용자에게 낸다(§5).

받은 골자로 `docs/stages/NN-*.md` 를 채운다. 반드시 들어갈 것:

1. **직관** — 수식 없이 한 문장
2. **⚠⚠ 앞 단계가 실패하는 구체적 장면** — 기법을 먼저 소개하지 않는다. **구멍을 먼저 보인다**
3. **원리** — 최소 수식 + 항별 뜻 + **손으로 따라가는 장난감 예제**(문서 3건, 단어 4개)
4. **그림** — 필요하면 `viz-build`. ⚠ 장식용 그림은 감점
5. **⚠⚠ 깨지는 조건** — 언제 틀린 답을 내는가. **이 절을 비우지 마라**

⚠ 학습자 수준: **트랜스포머는 안다. RAG 내부는 모른다.** 비유는 트랜스포머 쪽에 건다. 전문용어는 첫 등장 시 괄호로 원어 + 한 줄 풀이.

## 3. 뼈대와 테스트를 준다 — ⚠⚠ 여기까지가 Claude 의 한계선 (§5-T)

### Claude 가 하는 것

- `src/raglab/*.py` 에 **시그니처 + 타입 힌트 + 독스트링 + `TODO` + `raise NotImplementedError`**
- `tests/test_stageNN_*.py` 에 **통과 조건**. 명세를 주는 것은 대필이 아니다
- ⚠ 테스트에 **「깨지는 조건」 테스트를 반드시 포함**한다(§10 원칙 3). 빈 문서, 0 벡터, 후보보다 큰 top_k

### Claude 가 하지 않는 것

- `TODO` 자리를 채우는 것 → **`guard_handson` 훅이 기계적으로 막는다**
- 채팅에 정답 코드를 띄우는 것 — 파일에 안 썼을 뿐 대필이다

### 실습 강도 (§0-2 A2)

- **Stage 1~5** — 빈칸 채우기. 시그니처·독스트링·테스트를 다 준다
- **Stage 6~11** — 백지. **명세와 테스트만** 주고 파일 구조부터 사용자가 정한다

⚠ 사용자가 막히면 §4 로 간다. **뼈대를 더 채워 주는 방향으로 도망가지 마라.**

## 4. 사용자가 구현한다 — 막히면 `hint`

`hint` 스킬은 **단계적 힌트**를 준다. 정답이 아니라 방향이다.

⚠⚠ **사용자가 답답해하는 것과 명시적으로 대필을 요청하는 것은 다르다.** 먼저 힌트를 시도한다. 명시적 요청이 오면 §5-T 예외 절차를 따른다(override 등재 + `PROGRESS.md` 기록).

코드를 다 썼다고 하면 **`code-coach` 에 위임**해 진단만 받는다.

## 5. 테스트 → 중간결과를 눈으로 본다

```bash
.venv/Scripts/python.exe -m pytest tests/test_stageNN_*.py -q
```

통과하면 **끝이 아니다.** `labkit.inspect` 로 중간 산출물을 찍어 본다:

- Stage 1 — 청크 목록과 경계. **어디가 잘렸는지 눈으로**
- Stage 2 — 어떤 단어가 어느 차원인지, 상위 가중치 단어
- Stage 3·4 — 검색 후보와 **점수**. 왜 1등이 1등인지
- Stage 7 — 걸어간 경로. 어떤 트리플을 밟았는지

**⚠⚠ 눈으로 본 적 없는 값은 이해한 값이 아니다.** 블랙박스 한 방 호출 금지.

## 6. 기준선과 나란히 측정 (§5-D')

Stage 3 부터는 매 단계 측정한다.

- 결과를 `outputs/metrics/stageNN.json` 에 남긴다. **이게 쌓인 것이 README 결과 표가 된다**(§13)
- **아무것도 없는 기준선**(무작위 k건 / 앞에서 k건)을 항상 포함
- **바뀐 지표 전부**를 본다. 하나만 좋아진 것을 보고하지 않는다
- ⚠⚠ 수치가 이상하게 좋으면 **먼저 골든셋 오염을 의심한다**(§5-E')
