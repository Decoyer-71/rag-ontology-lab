# 복습 — 인출로 한다

`../../CLAUDE.md` §14. **이 절차의 전제는 하나다: 다시 읽기는 복습이 아니다.**

## ⚠⚠ 왜 「인출」이어야 하는가

2026-09-10 조사 결과(⚠2차 — 원문 PDF 접근이 막혀 2차 요약 경유):

- Dunlosky et al.(2013)은 10개 학습기법 중 **인출 연습·분산 연습을 최고 등급**,
  **다시 읽기를 최저 등급**으로 평가했다 ✅
- 「망각 곡선이 정한 최적 주기」는 **없다.** 에빙하우스(1885)는 피험자 1명·무의미 음절
  실험이고, 확장 간격이 우월하다는 통설은 Karpicke & Roediger(2007)이 지지하지 않는다
  (확장 간격은 단기에만 유리했고 장기에는 균등 간격이 나았다) ⛔·⚠논쟁중

그래서 이 절차는 **간격을 근거로 포장하지 않는다.** 대신 두 가지만 지킨다:

1. **간격을 둔다** — `labkit/review.py` 가 만기를 관리한다
2. **⚠⚠ 지난 강의를 다시 보여주지 않는다** — 사용자가 **먼저 떠올린 뒤에** 대조한다

⛔ *"Stage 2 에서 TF-IDF 를 이렇게 배웠죠"* 로 시작하지 마라. **그 순간 복습이 아니라 재수강이다.**

## 절차

### 1. 오늘 돌 카드를 확인한다

```bash
.venv/Scripts/python.exe src/labkit/review.py due
```

⚠ 상한이 걸려 있다(기본 5장). **더 있어도 오늘은 그만큼만 한다** — 사용자 시간이 가장 비싼
자원이고(§9), 벽을 세우면 재시작 자체가 막힌다.

⚠⚠ 출력에 **「Stage N 재방문」** 이 떠 있으면 카드를 돌리지 마라. 공백이 길다는 뜻이다.
→ 절차 5 로 간다.

### 2. 카드를 한 장씩 낸다 — **한 번에 하나**(§12-3)

#### 개념 카드 (`kind: concept`)

질문을 그대로 던지고 **기다린다.**

- ⛔ 힌트를 먼저 주지 마라. 막히는 것 자체가 인출이다
- 답을 못 하면 → `hint` 스킬로 수위를 올린다. **정답을 말해 주지 않는다**
- 답이 나오면 §14-2 기준으로 판정한다: **원리를 자기 말로 말했는가**

#### ⭐ 코드 카드 (`kind: code`) — 빈칸으로 되돌린다

**정답 키를 새로 만들 필요가 없다.** 사용자 본인의 구현이 git history 에 있고,
채점표는 `tests/` 가 이미 하고 있다.

**⚠⚠ 하드 전제 — 워킹트리가 clean 해야 한다**

```bash
git status --porcelain
```

비어 있지 않으면 **중단하고 사용자에게 커밋 또는 스태시를 요청한다.**
이 절차는 사용자 코드를 지운다. 커밋되지 않은 작업 위에서 절대 돌리지 마라.

**순서**

1. 카드의 `target`(`src/raglab/파일.py::함수`)에서 **그 함수의 본문만**
   `raise NotImplementedError("복습 — 다시 짜 보십시오")` 로 되돌린다
   - 시그니처·타입힌트·독스트링은 **남긴다.** 명세를 지우는 게 아니라 구현을 지우는 것이다
   - ⚠ 이건 §5-T 위반이 아니다. `guard_handson` 은 `NotImplementedError` 가 **줄어들 때**
     막는다. 늘리는 방향이라 통과한다
2. 사용자가 **직접 다시 짠다.** 막히면 `hint` 스킬. ⛔ 채워 주지 않는다
3. 채점은 감이 아니라 테스트로 한다:
   ```bash
   .venv/Scripts/python.exe -m pytest <카드의 test> -q
   ```
4. **통과** → 새 구현을 그대로 둔다(사용자 본인 코드다). 그리고 **이때 처음으로**
   옛 구현과 나란히 보여준다:
   ```bash
   git diff -- <파일>
   ```
   ⚠⚠ **여기가 이 카드의 가장 값진 순간이다.** 같은 사람이 같은 문제를 두 번 풀었는데
   어디가 달라졌는가 — 그게 무엇을 이해했고 무엇을 잊었는지를 보여준다
5. **실패** → 두 번째 시도까지 준다. 그래도 안 되면 원상복구하고 실패로 채점한다:
   ```bash
   git checkout -- <파일>
   ```
   ⛔ **실패 전에 옛 구현을 보여주지 마라.** 그건 인출이 아니라 베끼기가 된다

### 3. 채점을 기록한다

```bash
.venv/Scripts/python.exe src/labkit/review.py grade --id <카드id> --ok
.venv/Scripts/python.exe src/labkit/review.py grade --id <카드id> --fail
```

- 성공 → 간격이 늘어난다 / 실패 → 간격이 1일로 되돌아간다
- ⚠⚠ **관대하게 채점하지 마라.** "거의 맞았으니 통과"는 다음 달의 자신을 속이는 것이다
- 채점하면 게이트가 자동으로 갱신된다. 배정된 카드를 다 돌면 **저절로 열린다**

### 4. 기록 — §13-3 의 재료다

`docs/PROGRESS.md` 의 복습 절에 한 줄 남긴다. **틀린 것을 반드시 적는다.**

```markdown
- 2026-MM-DD 복습: s02-compute_idf 실패 — IDF 분모의 +1 이 왜 있는지 못 말함.
  Stage 2 §원리 로 되돌아감
```

⚠⚠ **「무엇을 잊었는가」가 「무엇을 배웠는가」보다 강한 재료다.** 매끈하게 성공만 적힌
복습 기록은 읽는 사람이 안 믿는다(§13-3).

### 5. ⚠ 공백이 길 때 — 카드가 아니라 단계 재방문

`due` 출력에 **「Stage N 재방문」** 이 떴다면(기본 30일 이상 공백):

- 카드 다섯 장을 던지지 마라. **다 틀리고 사기만 떨어진다**
- 대신 그 단계의 `docs/stages/NN-*.md` **「이 단계에서 무엇을 할 수 있게 되는가」한 문장**만
  먼저 읽게 하고, `checkpoint` 의 「왜」 질문 **하나**로 지금 어디까지 남았는지 잰다
- 그 결과로 재방문 범위를 정한다. **전체를 다시 하지 않는다**

## ⚠ 이 절차를 건너뛰고 싶어질 때

- *"오늘은 새 걸 하고 싶은데요"* → §14-4 가 정확히 그걸 막는다. 카드 몇 장이 5분이다
- 정말 건너뛰어야 하면 **기록으로 남긴다**:
  ```bash
  .venv/Scripts/python.exe src/labkit/review.py skip --days 1 --reason "사유"
  ```
  ⚠ 건너뛴 횟수가 `review.json` 의 `skip_log` 에 쌓인다. **그것도 데이터다**
- ⛔ `review_session.json` 을 손으로 고쳐 게이트를 여는 것은 **측정 조작**이다.
  그렇게 열 거면 차라리 `skip` 으로 정직하게 열어라

## ⚠⚠ 파라미터를 근거처럼 말하지 마라 (§13-5)

`grow=2.0`·`floor_days=1` 은 **근거 없는 임의값**이다. 사용자에게 설명할 때
*"망각 곡선에 따라 2배씩 늘립니다"* 라고 말하면 **그건 사실이 아니다.**

정확한 표현: *"간격을 두고 스스로 인출한다는 원칙만 근거가 있고, 구체적 배수는 임의로
정한 출발점입니다. `outputs/metrics/review_log.json` 이 쌓이면 그 데이터로 고칩니다."*
