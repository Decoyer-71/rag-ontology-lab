# 그림·HTML 산출물 빌드

`../../CLAUDE.md` §8 산출물 규격의 실행 절차다.

## ⚠⚠ 먼저 — 그림이 필요한지부터 판단한다

**장식용 그림은 감점이다.** 다음을 만족할 때만 그린다:

| 그린다 | 그리지 않는다 |
|---|---|
| **숫자가 어떻게 변하는가**를 보여야 할 때 (TF-IDF 행렬 → 코사인 점수) | 개념 나열 (「RAG 는 검색 + 생성」) |
| **경로를 걸어가는 것**을 보여야 할 때 (3홉 그래프 탐색) | 텍스트로 세 줄이면 되는 것 |
| **두 방식의 차이**를 나란히 놔야 할 때 (글자수 청킹 vs 구조 청킹) | 이미 표로 충분한 것 |
| 파이프라인에서 **어디가 끊겼는지**를 짚어야 할 때 (A·B·C 실패 지점) | 예쁜 아키텍처 다이어그램 |

⚠ *"그림 한 장 있으면 좋겠다"* 는 이유로 그리지 마라. **무엇을 보여야 하는지 한 문장으로 못 적으면 그리지 않는다.**

## 그림 — 인라인 SVG

### 규격

- **인라인 SVG.** 외부 이미지 파일·CDN 금지(§8 오프라인)
- **양쪽 테마 대응** — 색을 하드코딩하지 말고 `currentColor` 나 CSS 변수를 쓴다.
  ⚠ 흰 배경 전제로 검은 선을 그으면 **어두운 테마에서 안 보인다**
- **한글 폰트를 지정하지 마라** — 시스템 폰트 스택에 맡긴다. 특정 폰트 지정은 다른 PC 에서 깨진다
- **글자 크기 최소 12px** — 축소돼도 읽혀야 한다
- 넓으면 `viewBox` + `max-width:100%` 로 컨테이너 안에서 줄어들게 한다

### ⚠ 내용 규율

- **실제 값을 쓴다.** 장난감 예제의 진짜 숫자를 넣는다. 지어낸 숫자를 그림에 넣으면 그건 `⚠⚠추론` 이다(§4)
- 화살표에 **무슨 뜻인지** 라벨을 단다. 화살표만 있는 그림은 정보가 없다
- 범례를 단다

## HTML 산출물

### ⚠⚠ 빌더를 쓴다 — 직접 문자열을 조립하지 마라

```python
from labkit.report import build_report
```

직접 조립하면 규격이 어긋나고, **`guard_claim` 훅에 막힌다**(합성 표기·「한계」 절 누락).

### 규격 (§8)

| 항목 | 규격 |
|---|---|
| **자기완결** | CSS·JS·그림 전부 파일 안에. 그림은 인라인 SVG 또는 base64 |
| **오프라인** | 외부 CDN·폰트·이미지 요청 **금지** |
| **테마** | 밝음/어두움 양쪽 (`prefers-color-scheme`) |
| **반응형** | 넓은 표·그림은 **자기 컨테이너 안에서** 가로 스크롤. 본문은 가로 스크롤 금지 |
| **한국어** | 본문 한국어 · 존댓말 · 전문용어 첫 등장 시 괄호로 원어 |
| **구조** | ① 한눈 요약 ② 문제 정의 ③ 데이터 ④ 방법(직관→원리→가정) ⑤ 결과 ⑥ **한계와 오용 경고** ⑦ 재현 방법 |
| **근거 등급** | §4 등급 표기 + 상단 범례 |
| **⚠⚠ 합성 표기** | 최상단 배너. `build_report(..., synthetic=True)` |

### ⚠⚠ 빼면 안 되는 두 가지

1. **합성 배너** — `data/synthetic/` 은 전부 가상이다. 표기 없이 나가면 그 수치가 실세계 성능으로 읽힌다. **틀린 것보다 나쁘다**(§3-S)
2. **「한계」 절** — 이 방법이 언제 틀린 답을 내는가. 빼면 그 문서는 위험하다(§8 구조 ⑥)

둘 다 `guard_claim` 훅이 기계적으로 확인한다. 막히면 **훅이 틀린 게 아니라 문서가 미달인 것이다.**

## 수치를 실을 때 (§4 · §5-D')

- **모든 수치에 분모.** "Recall@5 = 0.72" 가 아니라 "0.72 (골든셋 25문항 중 18)"
- **기준선과 나란히.** 개선폭만 적힌 표는 규격 미달
- **근거 등급 표기.** `✅측정` / `⚠파생` / `⚠⚠추론` / `⚠2차`
- ⚠ 측정하지 않은 칸은 **빈칸으로 두고 「미측정」이라고 적는다.** 추정치로 메우지 마라(§13-5)

## 검증 — 내보내기 전에

1. **파일을 실제로 열어 본다.** 브라우저 도구로 렌더링 확인
2. **어두운 테마로도 본다** — 여기서 그림이 안 보이는 사고가 자주 난다
3. **좁은 폭으로 본다** — 본문이 가로로 밀리는지
4. `verify` 에 통과시킨다(§5-C 대응) — 수치·등급·한계 절
5. `SendUserFile` 로 내보낸다 → `guard_claim` 이 마지막으로 확인한다
