# RAG · 온톨로지 실습실 (rag-ontology-lab)

> **라이브러리 없이 RAG 검색기와 지식그래프를 직접 구현하고, 각 기법이 검색 성능을 얼마나 올리는지 단계마다 측정한 학습 프로젝트입니다.**

`LangChain`·`faiss` 같은 프레임워크를 쓰지 않습니다. TF-IDF·BM25·RRF·코사인 유사도·그래프 탐색을 **numpy와 표준 라이브러리로 직접 짜서**, "왜 이 문서가 검색됐는가"를 끝까지 손으로 따라갑니다.

## 무엇을 만드는가

가상의 통신사 **한빛텔레콤** 고객센터 챗봇의 **검색 엔진**을 밑바닥부터 만듭니다.

> ⚠⚠ **한빛텔레콤과 모든 요금제·고객·수치는 교육용 합성 데이터입니다.** 실재하는 회사나 상품이 아닙니다. → [`data/DATA_CARD.md`](data/DATA_CARD.md)

두 가지 서로 다른 질문을 다룹니다.

| 질문 | 필요한 것 | 왜 |
|---|---|---|
| 「국제전화 요금 어떻게 돼?」 | **RAG (문서 검색)** | 답이 약관 어딘가에 **문장으로** 적혀 있다 |
| 「내 폰에서 쓸 더 싼 요금제 있어?」 | **온톨로지 (관계 그래프)** | 답이 **어떤 문서에도 없다.** 고객 → 단말기 → 호환 요금제 → 요금 비교, **3홉을 걸어가야** 만들어진다 |

두 번째 질문이 이 프로젝트의 핵심입니다. **문서 검색이 원리적으로 못 푸는 질문**이 무엇인지, 그리고 그때 무엇을 더해야 하는지를 코드로 보입니다.

## 실행

```bash
# 1. 가상환경 (uv 사용)
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt

# 2. 합성 코퍼스 생성 (이미 커밋돼 있으므로 재생성은 선택)
.venv/Scripts/python.exe data/make_corpus.py

# 3. 테스트 — 아직 구현 안 된 단계는 실패합니다 (정상)
.venv/Scripts/python.exe -m pytest tests/ -q

# 4. 전체 측정 재현
.venv/Scripts/python.exe -m src.raglab.run_all
```

새 PC에서 이어서 작업하려면 → [`docs/SETUP.md`](docs/SETUP.md)

## 한계

이 저장소가 **하지 않는 것**을 먼저 적습니다.

- **프로덕션 시스템이 아닙니다.** 학습용 실습실이며, 규모·동시성·장애 대응을 전혀 고려하지 않았습니다
- **주 코퍼스가 합성입니다.** 여기서 나온 수치를 실세계 RAG 성능으로 읽으면 안 됩니다. Stage 10의 실데이터 대조가 그 간극을 재는 유일한 장치입니다
- **문서 파싱(PDF·HWP·표)을 다루지 않습니다.** 실무 RAG 실패 원인 1위가 파싱인데, 이 저장소는 정제된 마크다운에서 시작합니다. 의도적인 범위 제한입니다
- **생성(LLM 호출) 단계는 선택입니다.** 검색과 규칙 검사까지가 본체입니다
