# DATA CARD

이 프로젝트가 쓰는 데이터의 **출처·라이선스·한계·답할 수 없는 질문**을 적습니다.
(`../CLAUDE.md` §3-S · §13-5)

> ⚠⚠ **결론 먼저 — 주 코퍼스는 전부 합성입니다.**
> 한빛텔레콤·요금제·고객·단말기·수치 전부 교육용 가상 설정이며 실재하는 회사나 상품이 아닙니다.
> 여기서 나온 어떤 수치도 **실세계 RAG 성능으로 읽으면 안 됩니다.**

## 1. 합성 코퍼스 — 한빛텔레콤 (주 데이터)

| 항목 | 값 |
|---|---|
| 위치 | `data/synthetic/` |
| 생성 방법 | `data/make_corpus.py` — 결정적(deterministic). 재실행하면 같은 결과 |
| 라이선스 | 자유 사용 (이 저장소가 만든 것) |
| 개인정보 | **없음.** 등장 인물은 전부 가상 |
| 커밋 여부 | ✅ 커밋함 — 재현성을 위해 생성기와 결과물을 함께 둔다 |

### 규모 (2026-09-10 실측)

| 자산 | 수량 |
|---|---|
| 문서 | 15건 (마크다운, YAML front matter 메타데이터 포함) |
| 트리플 | 49건 (주어–술어–목적어) |
| 요금제 속성 | 7건 (수치 비교용 — 트리플로는 대소 비교가 안 되므로 분리) |
| 개념 | 16건 (`concepts.yaml`) |
| 규칙 | 4건 (생성 후 검사용) |
| 골든셋 | 24문항 — **dev 16 / holdout 8** |
| 역량질문(CQ) | 12건 |

### 골든셋 유형 분포

| 유형 | 문항 | 무엇을 재는가 |
|---|---|---|
| 단일사실 | 6 | 한 청크 안에 답이 있는 기본형 |
| 비교종합 | 5 | 여러 청크를 합쳐야 답이 된다 (교본 STEP 1 — 어려운 유형을 반드시 섞는다) |
| 코드조회 | 3 | 요금제코드·조항번호. **벡터 검색이 약한 유형** |
| 용어 | 4 | 사내 약어. **개념사전 없이는 빗나간다** |
| 관계 | 3 | **문서에 문장으로 없다.** 그래프를 걸어야 한다 |
| 부재 | 3 | ⚠ **문서에 답이 없다.** 「확인되지 않습니다」가 정답 (B형 실패) |

### ⚠⚠ 이 데이터로 **답할 수 없는** 질문

- **"실무 RAG 는 Recall 이 얼마나 나오나"** — 여기서 나온 수치는 이 코퍼스에 대한 것뿐입니다
- **"어떤 임베딩 모델이 한국어에 제일 좋은가"** — 문서 15건으로는 모델 비교가 성립하지 않습니다
- **"청킹 전략 A가 B보다 낫다"** — 이 코퍼스의 문서 구조에서만 참입니다
- **실제 통신사의 요금·약관·정책** — 전부 지어낸 것입니다

### ⚠⚠ 가장 큰 한계 — **내가 심은 구조만 발견됩니다**

`make_corpus.py` 는 학습이 재현할 수 있도록 함정을 **일부러** 심어 두었습니다.

| 심은 것 | 어느 단계가 밟는가 |
|---|---|
| 요금표를 **표**로 넣음 | Stage 1 — 글자수 청킹이 행을 자른다 |
| 구버전(2025)·신버전(2026) 요금안내를 **둘 다** 넣음 | Stage 4 — 유효일자 메타데이터 필터 |
| 요금제 코드(`5G-STD-69`) | Stage 4 — 벡터로 못 찾는다 → BM25 필요 |
| 「환불」과 「청약철회」를 다른 문서에 다른 말로 | Stage 3·6 — 동의어 연결 |
| 「3망 해지」·「W코드」를 **어느 문서에도 정의하지 않음** | Stage 6 — 개념사전이 필요해진다 |
| 3홉으로만 닿는 답 | Stage 7 — 그래프 탐색 |
| 답이 없는 질문 3건 | Stage 5 — B형 실패 분해 |

⚠ **이걸 「발견」이라고 부르면 안 됩니다.** 심어 둔 것을 다시 꺼낸 것입니다.
합성에서 얻은 결론이 어디까지 살아남는지 재는 장치는 **Stage 10 (KorQuAD 이식)** 하나뿐입니다.

## 2. KorQuAD 1.0 — 실데이터 (Stage 10 대조용)

| 항목 | 값 |
|---|---|
| 출처 | https://korquad.github.io/ |
| 내용 | 한국어 위키백과 문서 1,560건 · 문단 10,645개 · 질문–답변 66,181쌍 |
| **라이선스** | ⚠⚠ **CC BY-ND 2.0 KR** |
| 위치 | `data/external/` |
| 커밋 여부 | ⛔ **커밋 안 함** |
| 받는 법 | `.venv/Scripts/python.exe data/fetch_korquad.py` |

### ⚠⚠ ND = No Derivatives — 재배포·파생 금지

**이 저장소에 KorQuAD 파일을 커밋하면 라이선스 위반입니다.**

- `.gitignore` 의 `data/external/` 줄을 **지우지 마십시오** (`CLAUDE.md` §6 지뢰 7)
- `.claude/settings.json` 의 `deny` 규칙도 같은 목적입니다
- 각자 `fetch_korquad.py` 로 내려받습니다 — 저장소는 **다운로드 방법만** 제공합니다
- 가공한 청크·인덱스도 파생물이므로 커밋하지 않습니다

### 왜 이 데이터를 쓰는가

합성 코퍼스는 **제가 답을 알고 만든 것**입니다. 그래서 거기서 나온 수치는 자기충족적일 수 있습니다.
KorQuAD 는 **사람이 실제로 만든 질문**과 **제가 안 쓴 위키 문서**로 되어 있어,
Stage 1~9 에서 얻은 결론이 **다른 데이터에서도 살아남는지**를 잽니다.

⚠ 한계도 분명합니다 — KorQuAD 의 위키 문단에는 **사내 약어도, 다단계 관계도 없습니다.**
그래서 Part 2(온톨로지) 부분은 이 데이터로 검증할 수 없습니다. 그 사실을 리포트에 적습니다.

## 3. 검토했으나 쓰지 않은 데이터

⚠ 생존자 편향을 막기 위해 **탈락한 후보도 남깁니다.**

| 후보 | 왜 안 썼는가 |
|---|---|
| [allganize/RAG-Evaluation-Dataset-KO](https://huggingface.co/datasets/allganize/RAG-Evaluation-Dataset-KO) | 금융·공공 **PDF** 기반이라 파싱이 선행합니다. 이 프로젝트는 파싱을 범위 밖으로 뒀습니다(README 「한계」). 첫 학습용으로는 난도가 부적합 |
| 공공데이터포털 API | API 키 발급·심사가 필요하고, 표 형태 데이터라 RAG 문서 코퍼스로 부적합 |
| DBpedia / Wikidata 한국어 덤프 | 트리플은 풍부하나 **대응하는 문서 코퍼스**가 없어 RAG–온톨로지 결합 실습이 성립하지 않음. 덤프 크기도 부담 |

### ⚠ 찾지 못한 것

**한국어로, 문서 코퍼스와 다단계 관계 구조를 함께 갖춘 공개 데이터셋은 찾지 못했습니다.**
(2026-09-10 조사 기준)

이것이 주 코퍼스를 합성으로 만든 이유입니다. 교본이 쓴 「한빛텔레콤」 가상 사례를 그대로 구현했습니다 —
교본을 읽은 사람이 바로 이어서 손으로 짤 수 있다는 이점도 있습니다.

## 4. 수치를 인용할 때 지킬 것

- **모든 비율에 분모를 붙입니다.** "Recall@5 = 0.72" 가 아니라 **"0.72 (골든셋 dev 16문항 중 11.5)"**
- **기준선과 나란히 놓습니다** (`CLAUDE.md` §5-D')
- **근거 등급을 표기합니다** — `✅측정` / `⚠파생` / `⚠⚠추론` / `⚠2차`
- ⚠⚠ **합성 배너 없이 수치를 내보내지 않습니다.** `guard_claim` 훅이 기계적으로 막습니다
