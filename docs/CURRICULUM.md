# 커리큘럼 — 12단계 설계도

`../CLAUDE.md` §10 의 상세판입니다. **왜 이 순서인지**를 적습니다.

> ⚠ 각 단계의 강의 문서(`stages/NN-*.md`)는 **그 단계에 도달했을 때 채웁니다.**
> 미리 다 써 두면 학습자의 실제 막힘과 무관한 설명이 됩니다.

---

## 설계 원칙 셋

1. **개념 하나당 돌아가는 코드 하나.** 설명만 있는 학습은 남지 않습니다
2. **직접 구현 → 참조 구현 대조.** 라이브러리가 무엇을 대신해 주는지 알아야 그 한계도 압니다
3. **⚠⚠ 틀리는 예제를 같이 만듭니다.** 언제 깨지는지를 본 사람만 그 방법을 압니다.
   **잘 되는 예제만 있는 튜토리얼이 가장 해롭습니다**

이 셋이 테스트 설계에도 그대로 들어가 있습니다 — `@pytest.mark.breaks` 가 붙은 테스트가
「깨지는 조건」을 고정합니다.

---

## ⚠⚠ 순서를 지켜야 하는 이유

교본 §3-1 의 지적을 그대로 따릅니다.

> *"3단계를 0단계와 동시에 하면, 오답이 줄었을 때 그게 검색 개선 덕인지 용어 사전 덕인지 알 수 없습니다.
> 한 번에 한 변수만 바꿔야 다음 판단이 가능합니다."*

그래서 **한 단계에 한 기법만** 더합니다. 그리고 매번 직전 수치와 나란히 놓습니다(§5-D').

## 단계별 설계

### Stage 0 — 채점표부터 만든다

| 항목 | 내용 |
|---|---|
| **능력 목표** | 골든셋과 역량질문이 **왜 코드보다 먼저인지** 설명하고, 이 코퍼스의 채점표를 읽고 유형별로 무엇을 재는지 짚을 수 있다 |
| 교본 대응 | RAG STEP 1 · 온톨로지 STEP 1 |
| 코드 | ⛔ 없음. **읽고 이해하는 것이 과업** |
| 테스트 | `tests/test_stage00_goldenset.py` (8건 — 이미 통과) |
| 핵심 | 교본이 실패 1순위로 꼽은 것이 *골든셋 없이 튜닝한다* 다. 체감으로 판단하면 튜닝이 미신이 된다 |
| ⚠ 확인 | dev/holdout 이 왜 나뉘어 있는지, 「부재」 유형이 왜 필요한지 |

⚠ 이 단계에서 골든셋에 **문항을 몇 개 추가해 보는 것**을 권합니다. 만들어 봐야 왜 어려운지 압니다.

### Stage 1 — 문서를 구조로 자른다

| 항목 | 내용 |
|---|---|
| **능력 목표** | 글자수 청킹이 이 코퍼스에서 **무엇을 깨뜨리는지 측정으로 보이고**, 구조 단위로 자르는 코드를 짤 수 있다 |
| 교본 대응 | RAG STEP 2·3 |
| 파일 | `src/raglab/chunking.py` (빈칸 채우기) |
| 테스트 | `test_stage01_chunking.py` (12건, 그중 `breaks` 3건) |
| 심어 둔 함정 | `plans_2026.md` 의 **요금표**. 글자수로 자르면 행이 잘린다 |
| ⚠ 깨지는 조건 | 겹침 ≥ 크기 → 무한 루프 · 표 중간 절단 · 너무 짧은 청크는 문맥이 사라진다 |

**왜 첫 코드가 청킹인가** — 교본은 RAG 실패 1위를 알고리즘이 아니라 파싱·청킹으로 꼽습니다.
**여기서 깨진 것은 뒤 단계를 아무리 고쳐도 못 살립니다.**

### Stage 2 — 의미를 숫자 배열로 (TF-IDF 직접 구현)

| 항목 | 내용 |
|---|---|
| **능력 목표** | TF·IDF 각 항이 **무엇을 보정하는지** 설명하고, 문서-단어 행렬을 numpy 로 직접 만들 수 있다 |
| 교본 대응 | RAG STEP 4 |
| 파일 | `src/raglab/embedding.py` |
| 테스트 | `test_stage02_embedding.py` (16건, `breaks` 2건) |
| ⚠ 깨지는 조건 | 한국어 조사("요금제는" ≠ "요금제") · 미등록 질의 → 0 벡터 |

**왜 신경망부터 안 쓰는가** — 신경망 임베딩은 *"왜 이 문서가 검색됐는가"* 를 손으로 따라갈 수 없습니다.
TF-IDF 는 각 차원이 단어 하나라 눈으로 볼 수 있습니다.
투명한 버전으로 「벡터 = 좌표」를 손에 익힌 뒤, **Stage 9 에서 교체해 개선폭을 잽니다.**
그때 비교 대상이 있어야 합니다.

⚠ 트랜스포머를 아는 학습자에게는 *"여러분이 아는 그 임베딩이 맞다. 토큰 하나가 아니라 문단 하나를 벡터 하나로 누른 것"* 이 출발점입니다.

### Stage 3 — 가까운 벡터 찾기 (코사인) · **첫 측정**

| 항목 | 내용 |
|---|---|
| **능력 목표** | 코사인 유사도가 **왜 크기가 아니라 각도**를 보는지 설명하고, 첫 Recall 수치를 낼 수 있다 |
| 교본 대응 | RAG STEP 4·5 |
| 파일 | `src/raglab/retrieval.py` (앞부분) |
| 테스트 | `test_stage03_dense.py` (11건, `breaks` 2건) |
| ⚠⚠ 여기서 처음 | **기준선 대조 측정**이 시작된다 (§5-D'). `outputs/metrics/stage03.json` |
| ⚠ 깨지는 조건 | 0 벡터 → nan · 동점 순서 비결정 · 요금제 코드를 못 찾는다 |

⚠⚠ **무작위 5건 기준선을 반드시 함께 잽니다.** 그걸 못 이기는 검색기는 실패한 검색기입니다.

### Stage 4 — BM25 + RRF + 메타데이터 필터

| 항목 | 내용 |
|---|---|
| **능력 목표** | 왜 벡터 검색만으로는 `5G-STD-69` 를 못 찾는지 설명하고, 그 구멍을 메우는 하이브리드 검색기를 짤 수 있다 |
| 교본 대응 | RAG STEP 5 (★ 효과 최대) |
| 파일 | `src/raglab/retrieval.py` (뒷부분) |
| 테스트 | `test_stage04_hybrid.py` (16건, `breaks` 4건) |
| 심어 둔 함정 | 요금제 코드 · **구버전 요금안내(2025)가 인덱스에 함께 있음** |
| ⚠ 깨지는 조건 | BM25 IDF 음수 · RRF 가 점수 차이를 버림 · 필터 후 후보 0개 |

**세 가지를 한 단계에 넣은 이유** — 셋 다 「후보를 고르는 방법」이고, 교본이 같은 STEP 에 묶었습니다.
다만 **측정은 셋을 따로 합니다.** 한꺼번에 넣으면 무엇이 효과였는지 모릅니다.

### Stage 5 — 틀린 답을 A·B·C 로 쪼갠다

| 항목 | 내용 |
|---|---|
| **능력 목표** | 실패를 검색 실패(A)·자료 부재(B)·생성 실패(C)로 분해하고, **각각의 처방이 왜 다른지** 설명할 수 있다 |
| 교본 대응 | RAG STEP 7 (★ 진단의 핵심) |
| 파일 | `src/raglab/evaluate.py` |
| 테스트 | `test_stage05_evaluate.py` (15건, `breaks` 1건) |
| ⚠ 깨지는 조건 | 생성 없이는 C 를 판정할 수 없다 — **판정 불가를 판정 불가라고 말하는 것**이 과업 |

> **"답이 틀렸다"는 진단이 아닙니다.**
> 교본 경험칙 — 초기 프로젝트 실패의 **60~70%가 A** 입니다.
> 모델을 바꿔서 해결하려는 시도는 이 통계를 모를 때 나오는 대표적 낭비입니다.

⚠⚠ 여기까지가 **Part 1(RAG)** 입니다. Stage 6 부터 Part 2(온톨로지)로 넘어갑니다.

### Stage 6 — 사내 용어를 개념으로 정규화 · **백지 시작**

| 항목 | 내용 |
|---|---|
| **능력 목표** | `concepts.yaml` 한 장이 검색을 얼마나 고치는지 **측정으로 보이고**, 질의 정규화·동의어 확장 모듈을 설계부터 직접 만들 수 있다 |
| 교본 대응 | 온톨로지 STEP 1~5 · **붙는자리 ①** |
| 파일 | ⚠ **백지.** 파일 구조부터 사용자가 정한다 |
| 테스트 | ⚠ 이 단계에서 함께 만든다 |
| 심어 둔 함정 | 「3망 해지」·「W코드」는 **어느 문서에도 정의가 없다** (Stage 0 테스트가 이를 고정) |

그리고 붙는자리 ① 만 해도 전체 효과의 상당 부분이 나온다고 합니다. **그걸 측정으로 확인합니다.**

⚠⚠ 여기서부터 **백지**입니다(§0-2 A2). 명세와 테스트만 받고 설계부터 직접 합니다.

### Stage 7 — 트리플을 걸어간다 (3홉)

| 항목 | 내용 |
|---|---|
| **능력 목표** | **문서 검색으로는 원리적으로 못 푸는 질문**이 무엇인지 보이고, 그래프 탐색으로 답을 만들 수 있다 |
| 교본 대응 | 온톨로지 STEP 4·7 · **붙는자리 ②** |
| 파일 | ⚠ 백지 |
| 재료 | `triples.csv` 49건 + `plan_attrs.json` (수치 비교용) |
| 채점표 | `competency_questions.yaml` — CQ 통과율 |

**이 단계가 이 프로젝트의 하이라이트입니다.**

> *"내 폰에서 쓸 수 있는 더 싼 요금제 있어?"*
> 이 답은 **어떤 문서에도 문장으로 적혀 있지 않습니다.** 만들어내야 합니다.
> 고객 → 보유 단말기 → 그 단말기와 호환되는 요금제 → 현재 요금제와 비교. **3홉입니다.**

⚠ 왜 트리플과 속성을 분리했는가: 트리플의 목적어가 문자열이면 **대소 비교가 안 됩니다.**
「더 싼」을 판정하려면 수치 표가 따로 필요합니다. 이것이 실무에서 자주 밟는 설계 함정입니다.

⚠ 깨지는 조건: 순환 참조 → 무한 루프 · 홉 수 제한이 실제로 안 걸림 · 방향성 간선을 양방향으로 걸음

### Stage 8 — 규칙 검사 + 파이프라인 통합

| 항목 | 내용 |
|---|---|
| **능력 목표** | 답변이 규칙을 위반했는지 **기계적으로** 검사하고, Stage 1~7 을 하나의 파이프라인으로 묶을 수 있다 |
| 교본 대응 | 온톨로지 STEP 7 · **붙는자리 ③** |
| 파일 | ⚠ 백지 |
| 재료 | `concepts.yaml` 의 `rules` 4건 |

규칙 예: *해지 진행 중인 고객에게 부가서비스를 추천하지 않는다* · *5G 미지원 단말기에 5G 요금제를 추천하지 않는다*

⚠ **LLM 호출(생성)은 선택입니다** (§9). 검색과 규칙 검사까지가 본체이고,
API 키가 필요하므로 이 단계 전에 **모아서 한 번에** 묻습니다.
생성이 없으면 「후보 5개 + 규칙 검사 결과」까지를 산출물로 합니다.

### Stage 9 — 신경망 임베딩으로 교체

| 항목 | 내용 |
|---|---|
| **능력 목표** | 트랜스포머의 은닉 상태가 어떻게 문장 임베딩이 되는지 설명하고, TF-IDF 대비 **개선폭을 숫자로** 낼 수 있다 |
| 교본 대응 | RAG STEP 4 심화 |
| ⚠⚠ 조달 | `torch` + `sentence-transformers` **약 2~3GB**. C 여유 19GB. **사용자 확인 필수** (§9) |

**여기서 트랜스포머 지식이 RAG 와 연결됩니다.**
지금까지 짠 TF-IDF 는 각 차원이 단어 하나였습니다. 신경망 임베딩은 그렇지 않습니다 —
차원 하나가 무엇을 뜻하는지 **아무도 모릅니다.** 그 대가로 「환불 ↔ 청약철회」를 이어 줍니다.

⚠ **투명성과 성능의 교환**이 이 단계의 주제입니다. 그리고 Stage 2 를 먼저 한 이유이기도 합니다.

⚠ 깨지는 조건: 공개 벤치마크 순위가 **우리 문서에서 재현되지 않는다**(교본 STEP 4).
그래서 **자체 골든셋으로 비교**합니다.

### Stage 10 — KorQuAD 실데이터로 이식

| 항목 | 내용 |
|---|---|
| **능력 목표** | 합성 코퍼스에서 얻은 결론이 **다른 데이터에서 어디까지 살아남는지** 재고, 그 차이를 설명할 수 있다 |
| 데이터 | [KorQuAD 1.0](https://korquad.github.io/) — ⚠⚠ CC BY-ND, 재배포 금지 |
| 받는 법 | `.venv/Scripts/python.exe data/fetch_korquad.py` |

**⚠⚠ 이 단계가 포트폴리오의 결정적 차별점입니다** (§13-2).

RAG 튜토리얼 저장소는 널려 있습니다. 대부분은 자기가 만든 예제에서 잘 돈다고 끝냅니다.
**합성에서 나온 결론을 실데이터로 검증하고 그 간극을 보고하는 것**은 희소합니다.
그게 *"분석을 할 줄 안다"* 의 증거입니다.

⚠ 한계도 분명히 적습니다 — KorQuAD 의 위키 문단에는 **사내 약어도 다단계 관계도 없습니다.**
그래서 **Part 2(온톨로지)는 이 데이터로 검증할 수 없습니다.** 그 사실을 리포트에 적습니다.
