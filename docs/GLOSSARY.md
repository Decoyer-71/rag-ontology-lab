# 용어 사전

⚠ **이 사전의 기준선**: 읽는 사람은 **트랜스포머 개념까지는 압니다.** RAG 내부 구조는 모릅니다.
그래서 어텐션·토큰·임베딩 차원 같은 말은 그냥 쓰고, **정보검색(IR) 쪽 용어에 풀이를 붙입니다.**

---

## 0. 큰 그림

### RAG (Retrieval-Augmented Generation, 검색 증강 생성)
LLM 에게 답하게 하기 전에, **우리 문서에서 관련 부분을 찾아 눈앞에 펼쳐 주는 것.**
오픈북 시험입니다. 그래서 품질의 대부분은 *"LLM 이 똑똑한가"* 가 아니라
**"올바른 페이지를 펼쳐 줬는가"** 에서 갈립니다.

### 온톨로지 (Ontology)
**우리 조직이 쓰는 말들의 목록과, 그 말들 사이의 관계를 기계가 읽을 수 있게 적어 둔 것.**
사전(단어 뜻) + 조직도(위아래) + 배선도(무엇이 무엇과 연결되는지)를 합친 문서입니다.

### 지식그래프 (Knowledge Graph)
온톨로지가 **빈 틀(스키마)** 이라면, 지식그래프는 **채워진 데이터**입니다.
- 온톨로지: "고객은 요금제에 가입한다"
- 지식그래프: "김민수 —[가입]→ 5G스탠다드"

### 트리플 (Triple)
**주어–서술어–목적어** 세 칸짜리 문장. 모든 지식을 이 형태로 적습니다.
`(김민수) -[가입]-> (5G스탠다드)`

---

## 1. RAG 구조

### 청크 (Chunk)
**검색의 최소 단위가 되는 문서 조각.** 문서 하나를 통째로 검색하면 관련 없는 내용이 딸려 오고,
너무 잘게 자르면 문맥이 사라집니다. 그 균형이 청킹의 본질입니다.

⚠ 함정: 글자 수로 자르면 **표와 조항이 잘립니다.**

### 임베딩 (Embedding)
**의미를 숫자 배열로 바꾼 것.** 비슷한 뜻 = 가까운 좌표.

> 트랜스포머를 아신다면: **여러분이 아는 그 임베딩이 맞습니다.**
> 다만 토큰 하나가 아니라 **문단 하나**를 벡터 하나로 누른 것입니다.
> 보통 마지막 은닉층을 토큰 축으로 평균 내거나 `[CLS]` 위치를 씁니다.

이 프로젝트에서는 **Stage 2 에서 TF-IDF(글자 통계)** 로 먼저 만들고,
**Stage 9 에서 신경망 임베딩으로 교체**해 개선폭을 잽니다.

### 메타데이터 (Metadata)
부서·문서종류·**유효일자**·접근등급·출처.
⚠⚠ **과소평가 1위입니다.** "2025년 약관"과 "2026년 개정 약관"을 구분하는 것은
벡터 유사도가 아니라 **유효일자 필터**입니다. 그리고 **나중에 넣으려면 전체 재색인**입니다.

### 인용 (Citation)
답변의 각 문장이 **어느 청크에서 왔는지**. 없으면 사용자가 검증할 수 없어 결국 아무도 안 씁니다.

## 2. 검색

### 키워드 검색 / 희소 검색 (Sparse Retrieval)
**글자가 일치하는 것**을 찾습니다. 요금제 코드 `LTE-S-33`, 약관 조항 번호에 강합니다.

### 벡터 검색 / 밀집 검색 (Dense Retrieval)
**뜻이 비슷한 것**을 찾습니다. "환불" ↔ "청약철회" 같은 의미 매칭에 강합니다.

⚠ 대신 `5G-STD-69` 와 `5G-PRM-89` 를 **거의 같은 자리로 뭉갭니다.**

### 하이브리드 검색 (Hybrid Retrieval)
위 둘을 합친 것. **실무 기본값**입니다. 교본이 "효과 최대" 로 꼽는 단계입니다.

### TF-IDF (Term Frequency–Inverse Document Frequency)
- **TF** — 이 단어가 이 문서에 몇 번 나오는가
- **IDF** — 이 단어가 **원래 흔한 단어인가.** 흔하면 일치해도 정보가 거의 없다

"요금"은 모든 문서에 있어 IDF 가 낮고, "청약철회"는 한 문서에만 있어 IDF 가 높습니다.

### BM25
TF-IDF 의 개선판. 세 가지를 합칩니다.
1. **IDF** — 흔한 단어의 기여를 깎는다
2. **TF 포화** — 같은 단어가 100번 나와도 10번의 10배가 되지 않게 (키워드 스터핑 방어)
3. **길이 정규화** — 긴 문서가 단지 길다는 이유로 이기지 않게

`k1`(포화 정도), `b`(길이 정규화 강도) 두 하이퍼파라미터가 있습니다.

### 코사인 유사도 (Cosine Similarity)
두 벡터의 **각도**로 재는 유사도. **왜 크기가 아니라 각도인가** — 문서가 길면 벡터가 커집니다.
크기를 보면 긴 문서가 무조건 이깁니다. 방향만 보면 길이에 흔들리지 않습니다.

### RRF (Reciprocal Rank Fusion, 역순위 융합)
여러 검색 결과를 **순위 기반**으로 합치는 법. 각 랭킹에서 순위 r 마다 `1/(k+r)` 을 더합니다.

⚠ **왜 점수를 안 더하는가** — 코사인은 [0,1] 이고 BM25 는 [0,수십] 입니다. **스케일이 다릅니다.**
그냥 더하면 BM25 가 항상 이깁니다. 순위는 스케일에 무관합니다.

⚠ 한계: **1등과 2등의 점수 차이가 버려집니다.**

### 재순위 (Rerank)
가져온 40개를 **다시 정밀 채점해 5개만** 남기는 단계. 교본이 "정확도 체감 개선이 가장 큰 단계" 로 꼽습니다.
⚠ 이 프로젝트에서는 Stage 9 이후 선택 항목입니다(Cross-Encoder 조달 필요).

## 3. 평가

### 골든셋 (Golden Set)
**평가용 정답 모음.** 질문 + 정답 근거 문서 + 기대 답변 + 유형.
⚠⚠ 교본은 **만들기 전에 채점표부터 만들라**고 합니다. 없으면 *"좋아진 것 같다"* 로만 판단하게 되고
튜닝이 미신이 됩니다.

### Recall@k (재현율)
**정답 근거가 상위 k 개 안에 들어온 질문의 비율.**
⚠ 분모는 **골든셋 문항 수**입니다. 검색된 문서 수를 분모로 쓰면 그건 **정밀도(precision)** 입니다.

### MRR (Mean Reciprocal Rank, 평균 역순위)
정답이 나온 순위의 역수 평균. 1위면 1.0, 4위면 0.25.
⚠ Recall 은 「찾았나」만 보고 MRR 은 **「몇 번째로 찾았나」**를 봅니다. **둘 다 봐야 합니다.**

### Faithfulness (충실도)
답변의 각 문장이 **근거 청크에 실재하는가.** 환각 여부를 재는 지표입니다.
⚠ 생성 단계가 있어야 잴 수 있습니다.

### 역량질문 (CQ, Competency Question)
**온톨로지의 골든셋.** 온톨로지를 그리기 전에 "이 챗봇이 답해야 할 질문"을 실제 문장으로 적습니다.
⚠ **CQ 에 나오지 않는 개념은 만들지 않습니다** — 과설계를 막는 유일한 장치입니다.

### A · B · C 실패 분해
⚠⚠ **"답이 틀렸다"는 진단이 아닙니다.** 원인을 셋으로 쪼갭니다.

| 유형 | 무엇 | 처방 |
|---|---|---|
| **A 검색 실패** | 정답 청크를 후보에 못 넣었다 | 하이브리드·재순위·질의 변환·청킹 재조정 |
| **B 자료 부재** | 문서에 답이 아예 없다 | ⚠⚠ **문서를 만들어야 한다. RAG 로는 못 고친다** |
| **C 생성 실패** | 찾고도 잘못 썼다 | 프롬프트 수정·컨텍스트 축소 |

교본 경험칙: 초기 프로젝트 실패의 **60~70%가 A** 입니다.

### 홀드아웃 (Holdout)
튜닝에 쓰지 않고 **따로 떼어 둔 평가 문항.**
⚠⚠ 튜닝에 쓴 골든셋으로 평가하면 그 수치는 **낙관 편향**돼 있습니다.

## 4. 온톨로지

### 용어의 계단
무엇이 하나씩 더해지는가:

| 단계 | 더해지는 것 |
|---|---|
| 용어사전 (Glossary) | 단어와 뜻 |
| 동의어사전 (Thesaurus) | **+ 같은 뜻 다른 말** — 해지 = 해약 = 취소 |
| 분류체계 (Taxonomy) | **+ 위–아래 계층** — 요금제 > 무제한요금제 > 5G무제한 |
| 온톨로지 (Ontology) | **+ 임의의 관계와 규칙** — 고객 —[가입]→ 요금제 |
| 지식그래프 (Knowledge Graph) | **+ 실제 데이터** — 김민수 —[가입]→ 5G스탠다드 |

### 클래스 · 인스턴스 · 속성 · 관계
- **클래스** — 개념 (고객, 요금제, 단말기)
- **인스턴스** — 실물 (김민수, 5G스탠다드)
- **속성** — 값 (월요금 69,000원)
- **관계** — 연결 (가입, 보유, 호환)

⚠ 교본: **명사(클래스)보다 동사(관계)가 챗봇 품질을 좌우합니다.**
관계가 없으면 그건 그냥 분류표입니다.

### 표면형 (Surface Form)
사용자가 **실제로 쓰는 표현.** 개념 하나에 여러 표면형이 붙습니다.
`CONCEPT:BULK_TERMINATION` ← "3망 해지", "전회선 해지", "통합해지", "한번에 해지"

⚠ 교본이 **투자 대비 1위**로 꼽는 작업입니다. 가장 값싸게 가장 큰 효과를 냅니다.

### 엔티티 링킹 (Entity Linking)
사용자 표현을 **올바른 개념에 연결**하는 것. "선약" → `CONCEPT:SELECTED_DISCOUNT`

### 홉 (Hop)
그래프에서 간선 하나를 건너가는 것.
*"내 폰에서 쓸 더 싼 요금제"* = 고객 → 단말기 → 호환 요금제 → 요금 비교 = **3홉**.
⚠⚠ **문서 검색은 이 경로를 걸어갈 수 없습니다.** 비슷한 문장을 찾을 뿐입니다.

### GraphRAG
RAG 에 그래프 탐색을 결합한 것. ⚠ 온톨로지가 RAG 파이프라인에 붙는 자리는 **딱 세 곳**입니다:
① 질의 변환(정규화·확장) ② 검색(개념·권한으로 후보 축소) ③ 생성 후(규칙 위반 검사)

**RAG 를 걷어내는 것이 아닙니다. 엣지 세 개를 더할 뿐입니다.**

## 5. 이 프로젝트에서 **의도적으로 안 쓰는 것**

⚠ 안 쓰는 이유가 있고, 그 이유를 아는 것이 학습의 일부입니다(`CLAUDE.md` §9).

| 용어 | 무엇 | 왜 안 쓰나 |
|---|---|---|
| **LangChain · LlamaIndex** | RAG 오케스트레이션 프레임워크 | **감추는 부분이 학습 대상**이다. 몇 줄로 돌아가는 데모는 변별력이 0 |
| **faiss · Chroma · Pinecone** | 벡터 DB | 문서 15건에 필요 없다. 교본도 *"DB 선택이 병목인 경우는 거의 없다"* 고 한다 |
| **HNSW · IVF** | 근사 최근접 탐색(ANN) 알고리즘 | 수백만 벡터에서 의미가 있다. 여기선 전수 계산이 더 빠르고 정확하다 |
| **Neo4j · Cypher · RDF/OWL · SPARQL** | 그래프 DB·표준 온톨로지 | 교본: *"그래프 DB 는 ①②③ 어디에도 필수가 아니다"*. YAML + 파이썬으로 충분 |
| **파인튜닝** | 모델 자체를 재학습 | ⚠⚠ **파인튜닝은 말투를 바꾸는 것, RAG 는 지식을 넣는 것.** 최신 요금제 반영하겠다고 재학습하는 건 대표적 오답 |

⚠ **면접에서 "왜 안 쓰셨나요"를 물어봅니다.** 위 표가 그 답입니다.
