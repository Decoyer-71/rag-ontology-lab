# 포트폴리오 합격선 체크리스트

`../CLAUDE.md` §13 의 실행 체크리스트입니다. **Stage 11 에서 이 목록을 한 줄씩 확인합니다.**

> 사용자 요구: *"학습수준은 기업지원에 포트폴리오로 제출할정도면 좋겠어"* (2026-09-10)

---

## ⚠⚠ 먼저 — 무엇이 이 저장소를 다르게 만드는가

**RAG 튜토리얼 저장소는 널려 있습니다.** LangChain 몇 줄로 돌린 데모는 **변별력이 0** 입니다.
채용 담당자는 그런 저장소를 하루에 여러 개 봅니다.

이 저장소가 다른 점은 셋뿐이고, **그 셋을 잃으면 다를 게 없습니다.**

| # | 차별점 | 무엇의 증거인가 | 어디서 나오나 |
|---|---|---|---|
| 1 | **직접 구현** — TF-IDF·BM25·RRF·코사인·그래프 탐색을 라이브러리 없이 | *메커니즘을 안다* | Stage 1~8 |
| 2 | **단계마다 기준선 대조 측정** — 각 기법이 Recall 을 얼마나 올렸는지 숫자로 | *튜닝을 미신으로 하지 않는다* | `outputs/metrics/` |
| 3 | ⚠⚠ **합성 → 실데이터 이식으로 한계를 잰다** | *자기 결과를 과대평가하지 않는다* | Stage 10 |

⚠ **1·2 만 있고 3 이 없으면 「잘 만든 튜토리얼」입니다. 3 이 있어야 「분석을 할 줄 아는 사람」입니다.**
3번이 가장 희소합니다.

## A. 60초 안에 읽히는가 (§13-1)

채용 담당자는 README 를 **끝까지 읽지 않습니다.**

- [ ] README **첫 화면**에 「무엇을 만들었고 수치가 얼마인가」가 있다
- [ ] **결과 표 하나 + 아키텍처 그림 하나**가 스크롤 없이 보인다
- [ ] ⛔ 설치 방법이 첫 화면에 오지 않는다
- [ ] 한 줄 요약이 **기술 나열이 아니라 결과**다
      - 나쁜 예: *"Python, numpy 를 활용한 RAG 시스템"*
      - 좋은 예: *"라이브러리 없이 검색기를 직접 구현하고 각 기법의 개선폭을 단계마다 측정한 학습 프로젝트"*

## B. 수치가 정직한가 (§13-5 · §4)

- [ ] 모든 비율에 **분모**가 있다 — "0.72" 가 아니라 "0.72 (dev 16문항 중 11.5)"
- [ ] **기준선이 같은 표에** 있다 — 무작위 k건 / 앞에서 k건 포함
- [ ] **떨어진 지표도 적혀 있다.** Recall 만 오르고 다른 게 내려갔으면 그것도
- [ ] ⚠⚠ **측정 안 된 칸이 추정치로 메워지지 않았다.** 빈칸은 「미측정」으로 둔다
- [ ] Recall@5 가 0.95 이상인 곳이 있으면 **오염을 확인한 근거**가 적혀 있다 (§5-E')
- [ ] `outputs/metrics/*.json` 이 실재하고 README 표와 **숫자가 일치한다**

## F. 코드 품질 (§13-4)

포트폴리오는 **코드를 읽힙니다.**

- [ ] 공개 함수 시그니처에 **타입 힌트**
- [ ] 독스트링이 **무엇을 하는지**가 아니라 **왜 그렇게 하는지**를 적는다
- [ ] `tests/` 전부 통과
- [ ] **깨지는 조건 테스트**(`@pytest.mark.breaks`)가 포함돼 있다
- [ ] 매직 넘버가 상수로 빠져 있고 **왜 그 값인지** 주석이 있다
- [ ] **시드가 고정**돼 있다 — 두 번 돌려 같은 수치가 나온다
- [ ] `requirements.txt` 가 **실제 설치분과 일치**한다
- [ ] `python -m raglab.run_all` 한 방으로 모든 수치가 재생성된다
- [ ] 커밋이 **단계별로 쪼개져** 있다. ⛔ 한 방 커밋 금지
